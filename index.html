The benchmark

From a real request
to a working revision.

Can a coding agent turn a user’s multimodal request into a complete, working revision of an existing application?

Each task pairs a normalized request with a runnable pre-edit application and hidden, expert-authored acceptance criteria. Requests can carry image, audio, video or document evidence. The criteria specify the requested outcomes and any preservation constraints while permitting any valid implementation — so no gold code or target screenshot is needed.

Read the abstract +

Evaluating human–AI co-design requires testing whether coding agents can translate real users’ multimodal requests into working application revisions. We introduce Co-Design Bench, a reference-free benchmark of 273 tasks curated from 37,463 deduplicated queries across 26,314 real user coding sessions. Its two tracks, Multimodal Editing (ME) and Repository Editing (RE), cover localized edits with optional image, audio, video, or document inputs and coordinated repository revisions. Tasks span three capability dimensions: Grounded Understanding, UI Transformation, and Functional Implementation. The tasks pair normalized requests and runnable pre-edit applications with 2,331 hidden expert-authored acceptance criteria. Our judge-then-refute protocol grades criteria using source and browser evidence, challenges positive verdicts with a separate LLM verifier, and audits visual and interaction claims without gold code or target screenshots. Under a shared agentic harness, the strongest of ten model endpoints passes an average of 69.9% of criteria per task but fully satisfies only 26.4% of tasks. All ten endpoints achieve lower criterion completion on repository edits spanning three or four change types than on those spanning one or two. Co-Design Bench provides a testbed for studying the gap between partial requirement satisfaction and complete task success under agentic execution for real-user application revisions.

Recovered, validated, then judged by experts.

What the tasks test

Three dimensions, nine categories, thirty capabilities.

Each task has one primary label for its main delivery objective; additional labels record its other required capabilities — 1,172 task–capability associations in all. 265 of 273 tasks carry multiple labels and 174 span more than one dimension.

How it compares

Real sessions, reference-free, adversarially checked.

Existing web-coding benchmarks cover reference reconstruction, synthetic or predefined edits, version-history edits, and repository issues. Co-Design Bench combines real-user revisions, five input modalities, reference-free acceptance, agentic evaluation and adversarial verification (paper, Table 1).

Task origins and evaluation capabilities of web-coding benchmarks
✓ reported× not reported△ subset or metric-dependentT / I / V / A / D = text / image / video / audio / document

Real-user sessions are requests from real-user coding histories, excluding standalone issue reports (DesignBench’s session requests belong to its editing subset). Reference-free acceptance needs no gold code or target screenshot; a pre-edit baseline is allowed. Agentic evaluation actively chooses tools and actions, beyond fixed test replay. Adversarial verification separately challenges initial positive verdicts. Definitions follow the paper’s Table 1.

    The evaluation

    Judge, then refute.

    Credit requires evidence that matches the claim.

    01 / Build

    Run the candidate

    The final application is mirrored into an isolated sandbox, built with Vite or served as static HTML, and rendered in headless Chrome. Failed builds or missing DOM nodes invalidate render-dependent criteria.

    02 / Gather

    Evidence per claim

    Source diffs establish static properties, screenshots support visual requirements, and recorded Playwright actions establish interactions and their resulting state. A handler in source alone cannot prove a feature is reachable.

    03 / Judge

    Verdict per criterion

    A fixed agentic evaluator grades every hidden criterion PASS, PARTIAL or FAIL, with the pre-edit baseline available to ground what had to change.

    04 / Refute

    Challenge every credit

    A separate LLM verifier re-examines PASS and PARTIAL verdicts for stubs, hardcoded outputs, unreachable entry points and failures under varied inputs. Audits abort scoring when required evidence is missing.
